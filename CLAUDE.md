# ISLA: notes for Claude

- **Every new bike needs its own sound profile.** In `data/bikes/<id>.json` add `sound.parts` next to the engine `sound` values. Keys (all optional multipliers, neutral = 1): `sq`/`sqHz`/`hiss` brake squeal level, pitch (Hz, default 1700), pad hiss; `chain`/`chainHz`/`lash` chain whirr and on/off-throttle clunk (use 0 for belt/shaft bikes); `clutch` plate rasp; `thump`/`thumpHz` suspension and road-joint thump (pitch below 1 = heavier); `rattle` loose body panels (0 = none, scooters ~1); `key`/`keyHz` key and switch clicks; `tink`/`tinkHz` exhaust cooling ping; `peg` peg/fairing grind. Base it on the real bike's brakes, drivetrain, weight and body, and compare with the existing four. Read by `pv()` in `js/audio.js`.
- **Engine sound is computed from the real engine:** `engine.geo` = `{bore, stroke (mm), cr, peak (peak-power rpm)}` -> header / muffler / intake acoustics (`acoustics()` in `js/spec.js`, synthesized by `js/engine-worklet.js`). Part options that change the engine carry physical keys: `ccx` (displacement x, bore-up), `crd` (+compression points), `evo` (exhaust opens degrees earlier, cam), exhaust `muf` (muffler volume vs stock, 0 = open pipe) and `hdr: 1` (tuned aftermarket header). Parts with no physical number put their sound on the option as summed levels (0 = stock): `sIn` induction, `sBri` brightness, `sMech` valvetrain, `sPun` punch, `sRgh` idle roughness, `sCrk` overrun crackle. A new part gets its sound from these, no code change. `sound.pq`/`bq` = pipe / muffler damping, the rest are levels.
- **Every bike has fine tuning on the DYNO tab** (`js/tune.js`, optional for the player, all sliders at stock = untouched spec). A new bike needs `engine.tune` = `{fuel: [low, mid, high] % more fuel than stock that best power wants, ign: [low, high] degrees of advance left, knock: [low, high] degrees to the knock limit}` (carbs also `jets` = the carb's real jet series, `jet` = stock size, `scr` = 1 pilot screw / -1 air screw; a carb option can carry its own `jet`) plus the sliders + defaults: FI `fl fm fh il ih rl`, carb `mj nc ps ig`, all `ct idl` (`on: 'carb' | 'fi'` when the bike is sold both ways). Base the numbers on the real engine (emission-lean commuter, rich supercharged, compression). `node tools/sim.mjs <id> tune`.
- **Suspension per bike:** `chassis.travel` = the real wheel travel [front, rear] in m and `chassis.susp` = `{fork: 'tele' | 'usd', rear: 'twin' | 'mono' | 'link' | 'unit', reb: [f, r], dz: [f, r], prog: [f, r]}` (rebound / compression damping ratio, damping x per end, spring rate rise at full travel). A visible rear shock's thin rod is drawn with `rod()` in model.js so it moves with the wheel.
- Also do the usual new-bike steps from README (index.json, model/cluster, garage data).
- **Sidecar: only TMX and Macho expose the Parts option for now (owner wants all bikes eventually).** Every bike already carries the mount data; to enable one, add its `parts.sidecar` + `defaults.sidecar: 0`. For a new bike give it Give a new bike a top-level `"sidecar": {"struts": [[x, y, z, wallY], ...]}` (bike frame points in model ct coordinates -> height on the sidecar's bike-side wall; optional `dz` to slide the sidecar along the bike, default centres it on the wheelbase), the `parts.sidecar` Solo/Tricycle options (no `var`: the sidecar is built by `buildModel`, not the bike's builder), `defaults.sidecar: 0` and `sound.sc` overrides. Also a `"class"` label for the bike cards.
- **Garage bolt-ons come from one table:** `maker/parts-gen.mjs` (row per bike in `BIKES`: stock grip, tyre sizes, wire wheels / disc / handlebar mirrors / halogen / top box) writes `tires rims disc caliper mirrors swarm levers grips seat box hl aux glow wled` into every bike file; re-run it after editing, never hand-edit those parts. Saved setups and other players store an option's INDEX: only ever add options at the END of a list (never insert, reorder or remove). A new bike = a new row. Everything it adds must be VISIBLE on the model (owner's rule: no option that changes nothing you can see). Shape keys (`tyT tyW tyK tyS rimD dscK mirK boxK auxK`, any `glowC`/`wledC`) are in `shapeOf()` in model.js and rebuild the model; colour keys (`calC levC grpC seatC boxC hlC auxC`) only recolour in `applyLook()`. Drawn by `tyre()`, `wheelFaces()`, `controls()`, `fit()`; physics keys `rollx dragx offr` in spec.js / rapier.js. `swarm` = swing-arm length (row `arm`) or a scooter's Engine Support (row `es`): `swl` m the rear axle moves back, `krx`, `yrd`. Option `note` = the small text under its name. A bike may send at most 24 non-`int` part keys to other players (`check` enforces it). Look at it: `node tools/bikeref.mjs --shot dir --parts tires=3,box=1,...`.
- **Pedestrians are data:** `data/npc.json` (archetypes, outfits by colour role + optional parts, activities, ride settings, lines). Bodies, poses and the one-draw crowd are `js/figure.js` (shared with the rider on foot); brains `js/npc.js` (headless, `node tools/npc.mjs`); drawing/messages `js/npcfig.js`. A new pose: add it to `POSES` in figure.js and to the list in tools/npc.mjs. Buildings register a front door with `door()` in world.js.
- **Interiors, shops, drinks are data:** `data/interiors.json` (rooms per building type: size, colours, props, counter shops, people with poses; built as a pocket 300 m above the building, so friends/minimap still place you there), `data/shop.json` (items with price + `fx` effects, shops with items and walk-up door types, `treat` list for friends). Logic is headless (`js/interior.js`, `js/pool.js`, `js/shop.js`, `js/effects.js`; `node tools/interior.mjs`), drawing `js/interiorfig.js`, glue `js/places.js`, on-foot context button `js/act.js` (`addAct`). A new effect = one entry in `FX` (effects.js) + whatever reads it; a new prop kind = `PROPS`/`PROPBOX` in interior.js + a case in interiorfig.js `build()`. Friends (multiplayer social: wave/treat/cheers/call) are `js/social.js` + `cleanSoc` in server/worker.js (redeploy the relay for it). Browser check: `tools/places.mjs`.
- **Weather is one snapshot for everyone:** the relay (`server/wx.js` + `worker.js`) fetches Open-Meteo for a fixed Philippine point through the edge cache and sends rooms a `wx` message (after `hi`, then every 15 min by alarm); solo riders `GET /wx` (`js/wxnet.js`). Headless logic in `js/weather.js` (modes `cfg.wx`: live / clear / rain / storm, easing, road wetness `WX.wet` -> `ctx.wet`, lightning keyed on the clock second so a room sees the same, `wxSky()` light / fog numbers; `node tools/weather.mjs`), drawing + per-frame glue `js/wxfig.js` (GPU rain, one draw), light / sky / fog in `daynight.js`, wet road + puddles = `FOGU.wet` in the road material (world.js), rain bed + thunder in `audio.js`, the menu's sky `js/menusky.js`. Wet grip = `wetGrip()` in `js/tyre.js` (per tyre `wetg` / `aqua` from `maker/parts-gen.mjs`); `ctx.wet = 0` must leave the physics exactly as it was (`node tools/sim.mjs <bike> wet`). A relay change needs `npx wrangler deploy`.
- Push to main, never another branch. Bump `BUILD` in `js/config.js` and `?v=` in index.html on release.
- **Debug/test tools live in `tools/` (see `tools/README.md`).** Use them instead of reading code or running the game. Before every push: `node tools/test.mjs` (~5 s: static checks, headless physics invariants, determinism, fuzz, diff vs `tools/baseline.json`; after an INTENDED physics/data change `node tools/test.mjs --update`; `--full` adds the garage sweep). Others: `check.mjs` (release sync, import map, DOM ids, bike JSON + wiring), `sim.mjs <bike|all> <launch|start|brake|corner|wheelie|stall|idle|iss>` (real physics headless; `--part k=i`, `--set k=v`), `fuzz.mjs`, `sweep.mjs`, `bike.mjs [id]` (compare bikes), `new-bike.mjs <id> --from <bike>` (scaffold with TODO markers that `check` rejects). New bike: scaffold, fill in, `check` clean, `sweep`/`fuzz` pass, `test --update`. New physics scenario: add a function to `tools/sim.mjs`. Not covered: Rapier (walls/crashes/suspension), rendering, audio, UI, multiplayer (`tools/smoke.mjs` needs playwright).
- **The underground (Ilalim) is data:** `data/cave.json` (chambers with floor height / ceiling / kind, tunnels between them, the portal on the cave hall's wall). It sits far off the island at `origin` because the ground is one height per x,z (`H()` in world.js returns the cave floor there). Logic headless in `js/under.js` (shape, floor/ceiling, OBB walls, portals, camera fit; `node tools/under.mjs`), drawing `js/underfig.js`, glue `js/undergo.js`, light in `daynight.js` (`ctx.ug`). A new chamber = an entry in `chambers` + a tunnel; keep tunnels under 16 %.
- **The big city and the 11.93 islands are generated:** `node maker/city-gen.mjs` bakes districts (flats), the street grid, ~3000 buildings, Kambal / Perlas / sandbars into `data/map/island.json` (everything it adds carries a `g93` mark, so re-running replaces it). Change the tables there, re-run, then `node tools/roads.mjs` and `node tools/test.mjs`. Building type `park` (lawn, fountain, trees) is in world.js.
- **Grass is GPU-only:** `js/grass.js` (one instanced draw, no per-blade data: the vertex shader places, colours and sways tufts from two data textures baked from the terrain mesh). Where it grows = the per-vertex `gw` density in world.js's terrain loop (0 on sand, roads, towns, paddies, under building OBBs). Count / reach per preset in `LV`; Options > Grass (`cfg.grass`). `grassFrame` draws only the window of that square the camera can see (`instanceCount` per frame; `GRASS.full` = whole square, checked by `tools/smoke.mjs`).
- **Profile before optimising:** `node tools/prof.mjs` (JS ms per frame by function on the benchmark ride, `--alloc` for garbage per frame), `node tools/smoke.mjs --perf` (draw calls / triangles). A pass that only runs in some state (speed, night, drunk) must be run once in `warm()` (renderer.js) or its shaders compile mid-ride.
